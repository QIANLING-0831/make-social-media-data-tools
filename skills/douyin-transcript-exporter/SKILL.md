# 抖音数据与逐字稿导出

仅处理用户有权访问和使用的公开内容。主页采集通过豆包工作的真实浏览器完成；不调用未公开接口，不绕过登录、验证码、限流或访问控制，也不下载视频。

## 确认任务

开始前确定以下信息：

- 抖音主页、单条视频或分享短链。缺少来源时询问用户。
- 输出目标。提供飞书多维表格链接时写入飞书；用户选择本地或未指定飞书时，默认本地导出，不因缺少飞书链接阻塞采集。
- 主页视频数量，默认最新 5 条；单条链接忽略此项。
- 是否需要逐字稿，默认需要。
- 写入模式，默认增量去重。删除或覆盖已有飞书记录属于破坏性操作，必须在明确目标范围后再次获得用户确认。

分享短链先在浏览器中展开为最终 URL，再判断是主页还是视频。

## 数据契约

内部记录统一使用 [references/data-contract.md](references/data-contract.md) 的字段和状态。开始采集前阅读该文档；它是去重、失败记录和质量门槛的唯一来源。

要点：

- 使用 `video_id` 作为稳定主键，标准视频链接为 `https://www.douyin.com/video/<video_id>`。
- 互动数转换为整数；无法可靠识别时保留 `null`，不要猜成 0。
- 逐字稿失败时正文留空，并分别记录 `transcript_status=failed` 与 `failure_reason`；不得用说明文字冒充正文。
- 本地导出前运行 `scripts/export_local.py --validate-only`；需要落盘时由同一脚本生成 Markdown 和 `_all.json`。

## 采集

需要主页或详情页数据时，阅读 [references/douyin.md](references/douyin.md)。

1. 打开来源页面并检查登录态。需要登录时请用户接管浏览器；不要代填手机号、验证码或处理滑块。
2. 主页按页面展示顺序收集视频链接，按 `video_id` 去重。只需要最新 N 条时，获取足够的唯一记录后停止滚动；用户要求全部时，滚动至页面明确无更多内容或连续三次滚动都没有新 `video_id`。
3. 逐条打开详情页，提取作者、标题、介绍、发布时间及点赞、评论、转发。保存原始页面文本或错误摘要，便于失败重试。
4. 单条页面失败最多重试两次并采用递增等待；仍失败则记录错误，继续处理其余视频。不要让一条失败丢失整批进度。

## 获取逐字稿

默认使用豆包工作提供的页面抓取/逐字稿能力。分页接口返回总长度时，持续读取到末尾并按 offset 无重叠拼接；接口不提供分页元数据时，不虚构分页参数。

完整性检查：

- 正文为空或明显在句中截断时重试。
- 正文少于 50 个字符只是风险信号；结合视频时长、内容类型和结尾判断，不能直接认定失败。
- 仅检查数据契约列出的明确占位短语，不能把“获取”等常用词作为禁词。
- 首选能力失败且当前环境已安装 `doubao-video-extract` 时，可按其说明使用飞书妙记回退；不可用时记录失败，不假设该 Skill 一定存在。

每处理一条记录就更新内存结果；批量较大时每 5 条写一个 JSON 检查点。重启后按 `video_id` 跳过已完成记录，只重试 `failed` 项。

## 可选 AI 字段

用户未要求“只要基础数据”时，可基于标题、介绍和逐字稿生成：

- `topics`：1–3 个标签。飞书已有“选题方向”选项时只能从现有选项选择；本地输出没有预设集合时可生成简洁标签。
- `summary`：30–80 个汉字的一句话总结，不复述标题，不用“这条视频讲了”等套话。

逐字稿过长时优先使用开头、结尾和分段摘要，避免仅截取开头导致主题偏差。

## 输出

### 飞书多维表格

提供飞书链接时阅读 [references/lark-write.md](references/lark-write.md)。先验证身份、链接和字段，再按 `video_id` 增量写入。默认只新增缺失记录；用户明确要求更新时，只更新指定字段。

写入后读取本次记录做全量验证：主键唯一、必填字段存在、数值类型正确、逐字稿状态与正文一致。验证失败时只修复受影响记录，再复检。

### 本地文件

将内部记录数组保存为 UTF-8 JSON，然后运行：

```bash
python scripts/export_local.py input.json --output-root douyin_data
```

脚本会规范化 URL/互动数、按 `video_id` 去重、执行质量门槛，并生成每条视频一个 Markdown 文件和 `_all.json`。目标批次目录已存在时脚本会创建带递增后缀的新目录，不覆盖旧结果。

## 完成报告

报告来源、发现数、成功数、重复跳过数、失败数、逐字稿状态分布、输出位置及验证结果。若有失败，列出 `video_id` 和简短原因，不暴露 Cookie、令牌或完整页面调试信息。
